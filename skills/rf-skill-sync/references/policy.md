# 同步策略与边界

## 核心设计原则

### 1. 软链接优先
- **为什么不用拷贝？** 软链接确保 skill 更新后所有 agent 立即可用，无需重复拷贝
- **相对路径而非绝对路径**：`../../.claude/skills/xxx` 保证跨机器、跨用户可用
- **不覆盖真实目录**：如果目标位置是真实目录而非软链接，永远跳过并提示

### 2. 自动发现目标
- 自动扫描所有 `.* /skills/` 模式的目录（如 `.codex/skills`, `.cursor/skills`, `.zcode/skills`）
- 排除源目录 `.claude/skills` 自身
- 如果没有发现任何目标，回退到默认值 `.codex/skills`

### 3. 自排除机制
- `rf-skill-sync` 自身不会被同步，避免递归循环
- 这是硬编码规则，不通过配置修改

### 4. 幂等性
- 重复运行不会产生副作用
- 已存在且指向正确的软链接会被跳过
- 每次运行都会报告完整的变更摘要

## 边界规则

| 操作 | 行为 |
|------|------|
| 软链接已存在且指向正确 | 跳过 +1 |
| 软链接已存在但指向错误 | 删除后重建，新增 +1 |
| 是真实目录 | 跳过 +1，警告提示 |
| 是普通文件 | 跳过 +1，警告提示 |
| 软链接断连（源已删除） | 删除 +1 |
| 目标目录不存在 | 自动创建 |

## 风险控制

1. **永远不删除真实文件或目录**：只处理软链接
2. **预览模式优先**：建议用户首次运行先用 `--dry-run`
3. **变更摘要可见**：每次运行都输出清晰的统计（+新增 / -删除 / =已存在）
4. **无静默操作**：每个被跳过的异常情况都有提示

## Git 推荐配置

建议在项目 `.gitignore` 中添加：
```
.codex/
.cursor/
.zcode/
.agents/
```

这样软链接不会被提交到版本控制，`.claude/skills/` 作为唯一源被跟踪即可。
